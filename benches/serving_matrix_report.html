How to read this comparison

Input sizes are complete token counts with zero truncation. English uses the English checkpoint; the other language sweep uses the multilingual checkpoint. Translated refund and support states are padded to fixed token lengths; questions and labels remain English. This synthetic corpus measures serving costs. It does not establish language quality or compare the quality of the two checkpoints.

Decisive has one inference lane. llama.cpp can batch eligible requests across its configured slots. Both receive the same total CPU worker budget. Each engine is measured separately while the other is idle. No token, state or result cache is used. Every response is checked after timing against that engine’s serial output; Decisive is also checked against pinned SDK outputs within 1e-4, with unchanged decisions.

Successful throughput uses total completed requests divided by measured block wall time. The interval resamples paired whole-block ratios. Latencies include client/server HTTP, queueing and response parsing. This is finite closed-loop load, with startup and block drain; it is not an open-loop saturation test.
